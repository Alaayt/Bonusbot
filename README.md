# Bonusbot - مستشار عروض وبونصات 1xBet الذكي

بوت تيليجرام ذكي يشرح عروض وبونصات 1xBet للاعبين البالغين، يساعدهم على اختيار العرض المناسب، ويوجّههم للتسجيل بالبروموكود `VIP10IQ` — بدقة كاملة ودون اختراع أي شرط أو رقم غير موثّق.

## المكوّنات الرئيسية

| الجزء | الوصف |
|---|---|
| `app/bot/` | منطق بوت تيليجرام (aiogram 3): Handlers، Keyboards، States، Middlewares |
| `app/ai/` | تكامل OpenAI API، System Prompts، محرك RAG-lite، فحوصات الأمان (Guardrails) |
| `app/promotions/` | قاعدة معرفة العروض: schemas، مستخرج PDF، مستخرج ويب، منسّق العرض للمستخدم |
| `app/database/` | نماذج SQLAlchemy 2.0 (async) + migrations عبر Alembic |
| `app/admin/` | لوحة إدارة كاملة عبر أوامر تيليجرام (بدون الحاجة لتطبيق ويب منفصل) |
| `app/scheduler/` | مهمة APScheduler دورية لاكتشاف تحديثات صفحات العروض |
| `app/locales/` | نصوص وأزرار البوت الكاملة بالعربية، الإنجليزية، والفرنسية |
| `data/promotions/` | قاعدة معرفة العروض بصيغة JSON (29 ملفًا) |
| `data/raw_sources/` | النصوص الخام الأصلية لكل عرض كما وردت من المصدر |
| `docs/` | تقرير التدقيق، سياسات الخصوصية واللعب المسؤول، أدلة النشر والصيانة |
| `tests/` | 27 اختبارًا لمنطق الأعمال الأساسي |

## البدء السريع

```bash
cp .env.example .env
# عدّل .env: TELEGRAM_BOT_TOKEN, OPENAI_API_KEY, AFFILIATE_REGISTRATION_URL, ADMIN_IDS...

python -m venv .venv
source .venv/Scripts/activate   # أو .venv\Scripts\activate على Windows
pip install -r requirements.txt

python -m alembic upgrade head   # أو استخدم init_db() التلقائي عند تشغيل البوت أول مرة
python -m app.main
```

أو عبر Docker:

```bash
docker compose up --build
```

## قاعدة معرفة العروض: كيف تعمل ولماذا هي مصممة هكذا

**لن يخترع البوت أي شرط أو مبلغ أو تاريخ.** كل عرض مخزَّن كملف JSON مستقل في `data/promotions/<slug>.json` وفق سكيمة موحّدة (انظر `app/promotions/schemas/promotion.py`). الحقل `verification_status` يحدد الثقة:

- `verified`: نص كامل من المصدر الرسمي مستلم ومُدقَّق.
- `partial`: نص مستلم لكنه ناقص بعض الأرقام/الجداول - يظهر تنبيه صريح للمستخدم بذلك.
- `blocked`: لم يصل أي نص موثّق بعد - لا يُعرض أي تفصيل مختلق؛ يُحوَّل المستخدم للمدير إن سأل عنه.

> ملاحظة: 7 عروض من القائمة الأصلية لم يصل نصها بعد وتم **حذفها فعليًا** من `data/promotions/` بطلب صاحب المشروع (غير مطلوبة حاليًا). راجع `docs/link_audit_report.md` لقائمتها الكاملة وكيفية إعادة إضافتها لاحقًا عند الحاجة.

### لماذا لم تُجمع كل الروابط الـ32 آليًا؟

راجع [`docs/link_audit_report.md`](docs/link_audit_report.md): موقع `1xbet.fi` محجوب جغرافيًا في بيئة التطوير التي بُني بها هذا المشروع. تم اتباع تعليمات المشروع بحذافيرها: **لم تُستخدم أي طريقة لتجاوز الحجب** (لا VPN، لا انتحال هوية). بدلاً من ذلك:
- 24 من 32 عرضًا أصليًا + 3 عروض إضافية: تم استلام نصوصها الكاملة يدويًا (نسخ ولصق من طرف صاحب المشروع) وتحويلها لقاعدة معرفة JSON منظمة.
- 7 عروض متبقية: محفوظة بحالة `blocked` بانتظار وصول نصها.
- عرض واحد (`chick_point`): تعارض مصدر مباشر (الرابط أعاد محتوى عرض مختلف تمامًا) - موثّق ومُعلَّم صراحة، لا يُعرض للمستخدم حتى يُحل.

### كيف تُحدَّث العروض لاحقًا؟

عبر لوحة الإدارة (تيليجرام):
```
/admin_update_offer <slug>
# ثم أرسل نص الشروط كاملاً، أو ارفع ملف PDF مباشرة
```
يُحفظ التحديث كـ "معلّق" (`PendingUpdate` في قاعدة البيانات) بانتظار مراجعتك عبر `/admin_pending` قبل أن يُدمج فعليًا في ملف JSON (الدمج النهائي في ملف JSON يتم يدويًا حاليًا من قبل المطوّر/المشرف التقني - راجع [`docs/add_new_offer.md`](docs/add_new_offer.md)).

## محرك RAG-lite

بدل حشو كل بيانات العروض الـ36 داخل System Prompt (ممنوع صراحة في متطلبات المشروع ومكلف من ناحية Tokens)، `app/ai/rag/search.py` يسترجع فقط العروض الأكثر صلة بسؤال المستخدم عبر:
1. تطابق نصي فازي (rapidfuzz) على الاسم والفئة والكلمات المفتاحية المرادفة (يفهم اللهجات والأخطاء الإملائية).
2. ترجيح حسب حالة العرض (نشط > مجدول > منتهي) ودولة المستخدم.
3. استبعاد العروض غير الموثقة (`blocked`) من نتائج البحث العام تلقائيًا.

## System Prompts

مقسّمة لملفات منفصلة في `app/ai/prompts/` (وليست جميعها في مكان واحد ضخم):
- `system_identity.md` - الهوية، البروموكود، منع الهلوسة، حماية القاصرين، حماية البيانات.
- `persuasion.md` - أسلوب الإقناع المسموح والممنوعات الصارمة.
- `explain_offer.md` - ترتيب شرح أي عرض (مختصر ثم كامل).
- `troubleshoot.md` - بروتوكول "لم يصلني البونص".
- `manager_summary.md` - كيفية تلخيص المحادثة عند التصعيد للمدير.

## الأمان والامتثال

- **القاصرون**: أي تصريح بأن العمر أقل من 18 يوقف كل محتوى ترويجي فورًا (`app/ai/safety/guardrails.py::detect_minor_claim` + تعليمات صارمة في System Prompt كطبقة دفاع ثانية).
- **اللعب المسؤول**: لا وعود بالربح، لا تشجيع على تعويض الخسائر (`detect_loss_chasing`)، أمر `/stop_marketing` متاح دائمًا.
- **حماية البيانات**: لا طلب لكلمات مرور/OTP/بيانات بطاقات داخل تيليجرام؛ `scrub_sensitive_data()` يحذف أي بيانات حساسة قبل تخزينها أو تصعيدها للمدير.
- **مقاومة حقن التعليمات (Prompt Injection)**: أي نص من صفحات الويب يُعامل كبيانات فقط، ويُكتشف ويُتجاهل أي محاولة "تجاهل التعليمات السابقة" (`detect_prompt_injection_attempt`).

## ما يحتاج بيانات/إعدادات إضافية منك

راجع القسم الأخير من رسالة التسليم في المحادثة، أو ملخص "ما تم إنجازه وما ينقص" - أهمها:
1. `TELEGRAM_BOT_TOKEN` حقيقي لتشغيل البوت فعليًا (لم يُشغَّل ببوت تيليجرام حقيقي في هذه البيئة لعدم توفر Token). `OPENAI_API_KEY` متوفر بالفعل.
2. `AFFILIATE_REGISTRATION_URL` و`APP_DOWNLOAD_URL` الحقيقيان.
3. حل تعارض Chick Point إن احتجته لاحقًا (انظر تقرير التدقيق). أما العروض السبعة الأخرى غير المكتملة فتم حذفها بطلبك وليست مطلوبة حاليًا.
4. أرقام غير مؤكدة في بعض العروض الجزئية (VIP Cashback levels، متجر البروموكود، إلخ) - راجع تقرير التدقيق للقائمة الكاملة.
