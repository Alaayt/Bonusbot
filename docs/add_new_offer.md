# دليل إضافة عرض جديد أو تحديث عرض موجود

## الطريقة الموصى بها (عبر لوحة الإدارة)

1. من تيليجرام (بحساب أدمن مُدرج في `ADMIN_IDS`):
   ```
   /admin_update_offer <slug-جديد-أو-موجود>
   ```
2. أرسل نص الشروط كاملاً (نسخ ولصق من الصفحة الرسمية شاملاً قسم "الشروط والأحكام")، أو ارفع ملف PDF مباشرة.
3. سيُحفظ كتحديث معلّق. راجعه عبر:
   ```
   /admin_pending
   ```
4. اضغط "✅ موافقة". هذا يُسجّل الموافقة في قاعدة البيانات (Audit Log) لكن **لا يكتب تلقائيًا** فوق ملف JSON - الخطوة الأخيرة يدوية عمدًا لضمان مراجعة بشرية قبل نشر أي رقم:

## الخطوة اليدوية الأخيرة (للمطوّر/المشرف التقني)

1. افتح النص المعتمد (ظهر في رسالة `/admin_pending`).
2. استخرج منه القيم وفق سكيمة `app/promotions/schemas/promotion.py` (نفس بنية أي ملف موجود في `data/promotions/` كمرجع).
3. إن كان عرضًا جديدًا: أنشئ `data/promotions/<slug>.json` جديدًا.
   إن كان تحديثًا لعرض موجود: عدّل الملف الموجود مباشرة، وحدّث `last_checked_at` و`verification_status` إلى `verified`.
4. احفظ نسخة النص الخام الأصلي في `data/raw_sources/<slug>.txt` (للمرجعية والمقارنة المستقبلية من المجدول).
5. لا تنشر أي تغيير على البوت الحي دون إعادة تحميل الكاش:
   - إذا كان البوت يعمل، استدعِ `reload_promotions()` (يحدث تلقائيًا عند استخدام `/admin_toggle` لأي عرض، أو أعد تشغيل البوت).

## قواعد إلزامية عند تعبئة أي ملف JSON

- **ممنوع اختراع أي رقم/تاريخ/شرط غير موجود حرفيًا في النص المصدر.**
- أي قيمة غير مذكورة صراحة تُترك `null` مع ملاحظة في `important_warnings` أو حقل يحتوي `note_unconfirmed`.
- `source_url` يجب أن يبدأ بـ `https://1xbet.fi` (يُتحقق منه في `tests/test_promotion_schema.py`).
- `verification_status`:
  - `verified`: النص الكامل مستلم ومطابق تمامًا لما كُتب في JSON.
  - `partial`: بعض الحقول ناقصة - اذكرها صراحة.
  - `blocked`: لا نص موثّق بعد - اترك كل الحقول الفعلية فارغة (`{}`, `[]`, `null`).
- شغّل الاختبارات بعد أي تعديل:
  ```bash
  python -m pytest tests/test_promotion_schema.py tests/test_promotion_store.py -v
  ```

## إذا تعارض المحتوى بين نسختين (عربي/إنجليزي أو تحديث جديد يختلف عن القديم)

اعتمد النص **الأحدث والأكثر تحديدًا رقميًا**، وسجّل التعارض في `docs/link_audit_report.md` تحت قسم جديد، تمامًا كما تم مع عرض `chick_point` (راجعه كمثال).
